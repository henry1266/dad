# DAD 閱讀體驗與介面強化設計

日期：2026-08-23
狀態：設計已由使用者逐段確認，等待書面規格審閱

## 背景

DAD 是以 Flask 提供的易經互動網站，目前包含資料處理表單、六十四卦頁、三套 `impress.js` 投影片及風水個案頁。現有自動測試全部通過，64 卦與投影片亦可正常載入，但首頁資訊密度高、樣式分散於多個模板，且內容可用狀態沒有單一判斷來源。

實際測試發現，首頁列出 10 筆風水個案，但詳細頁全部顯示找不到檔案。清單與唯一存在的 `易經個案001.txt` 位於 `config_data/易經輸入端資料夾`，詳細頁卻讀取不存在的 `config_data/易經個案資料夾`。此外，`002` 至 `010` 只有清單項目，沒有內容檔。

本設計以「閱讀與查找優先」為第一階段，選定「東方編輯館」視覺方向，並維持現有 Flask、Jinja、原生 JavaScript 與 `impress.js` 技術棧。

## 目標

1. 讓使用者能從首頁快速搜尋及篩選卦文、投影片與風水個案。
2. 讓所有頁面對內容是否可讀採用同一判斷，修復可點擊但無內容的個案連結。
3. 將資料處理表單移至獨立工作台，讓首頁專注於閱讀。
4. 統一首頁、卦文、個案與錯誤頁的版面、導覽和無障礙行為。
5. 保留三套現有投影片內容及 `impress.js` 動態，只補強操作介面。
6. 保持伺服器端完整輸出；JavaScript 失效時仍可閱讀與操作核心流程。

## 非目標

- 不建立前後端分離應用、JSON 搜尋 API 或前端框架。
- 不建立全文索引；第一階段只搜尋卦序、卦名、投影片名稱及個案名稱。
- 不新增背景工作佇列、即時進度串流或資料庫。
- 不重新編排投影片內容與 3D 座標。
- 不補造缺少的風水個案 `002` 至 `010` 內容。
- 不修改或提交工作區目前既有的生成資料變更。

## 已鎖定決策

- 視覺方向：A「東方編輯館」，使用暖紙色、墨綠、黃銅色點綴與內容優先的層級。
- 功能優先：閱讀與查找。
- 風水缺檔政策：保留全部 10 筆清單；可讀者能進入，缺檔者顯示原因並停用。
- 資料處理位置：獨立「資料工作台」。
- 搜尋範圍：卦序／卦名、投影片名稱、個案名稱，並可依類型篩選。
- 投影片範圍：保留 `impress.js`，新增控制、說明、進度與返回入口。
- 技術路線：Flask 漸進式強化。

## 架構

### 內容目錄

新增一個小型內容目錄模組，成為閱讀介面的單一事實來源。它只負責掃描現有檔案並回傳一致的內容描述，不負責 HTML 呈現或資料生成。

每個內容項目至少包含：

- `kind`：`gua`、`slides` 或 `fengshui_case`
- `key`：穩定識別值，例如卦序或個案名稱
- `title`
- `url`：可讀項目才有可導覽網址
- `available`
- `unavailable_reason`
- `search_text`：正規化後的卦序、名稱及類型文字

目錄提供三個窄介面：

1. 建立完整首頁目錄。
2. 依穩定識別值取得單一項目。
3. 取得同類型項目的前一筆與下一筆。

檔案數量小，目錄在每次請求時重新讀取，不做跨請求快取。補入新檔後，下一次重新整理即可反映。

### 正式資料來源

風水個案清單與內容統一以 `YIJING_INPUT_PATH`，也就是 `config_data/易經輸入端資料夾` 為正式來源。移除未實際存在且會造成分岔的 `FENGSHUI_CASES_PATH` 與其環境準備複製項目，不提供雙路徑 fallback。

卦文與維基整理內容繼續使用現有生成資料路徑；投影片繼續使用現有產生器與素材目錄。

### 路由責任

- `GET /`：閱讀首頁，取得內容目錄與摘要統計。
- `GET /workspace`：顯示資料工作台與剛完成的一次處理結果；結果只透過 redirect 後的 session flash 傳遞，不建立長期歷史。
- `POST /workspace/process`：驗證 CSRF、範圍與明確選取的操作，執行後重新導向 `GET /workspace`。
- `GET /gua/<int:gua_number>`：使用目錄驗證範圍，呈現卦文及前後導覽；不存在的卦序回傳友善 404。
- `GET /fengshui/case/<path:case_filename>`：只呈現可讀個案；不存在或缺檔回傳友善 `404`。
- 現有三個投影片路由維持不變。

舊首頁表單與 `POST /process_interaction` 一併移除，不保留轉送或重複入口。

## 頁面與元件

### 共用頁框

新增 Jinja 共用頁框，供首頁、工作台、卦文、個案與錯誤頁延伸。共用內容包含：

- 跳至主要內容連結
- 品牌及主導覽
- 頁面主容器
- 頁尾
- 共用 CSS 與可選頁面腳本區塊

現有卦文與個案模板中的行內樣式移入共用樣式表。投影片因渲染模式不同，保留獨立基底模板，但使用同一色彩變數與字體策略。

### 閱讀首頁

首頁由上至下為：

1. 品牌導覽，包含典藏首頁、六十四卦、投影片、風水個案及資料工作台入口。
2. 主視覺、統一搜尋框及典藏狀態摘要。
3. 全部、六十四卦、投影片與風水個案篩選。
4. 六十四卦卡片清單。
5. 投影片及風水個案區塊。
6. 低干擾的資料工作台入口。

所有內容項目均由伺服器輸出。搜尋字串在伺服器端完成空白與英文字母大小寫正規化；原生 JavaScript 只依 `data-*` 搜尋欄位即時隱藏或顯示卡片，並更新結果數與空結果提示。沒有 JavaScript 時，全部項目仍然可見。

風水個案顯示 `可閱讀數 / 清單總數`。缺檔項目保留標題、顯示「缺少內容」及原因，但不使用 `<a>`，因此無法誤入錯誤頁。

### 卦文與個案頁

內容頁使用相同閱讀框架：麵包屑、標題、資料狀態、段落捷徑、正文及前後導覽。

卦文頁保留古文、維基參考及外部連結。段落捷徑只捲動到頁內錨點，不以 JavaScript 隱藏正文。底部顯示返回卦目錄、目前位置及上一篇／下一篇。

個案頁顯示標題及原始文字內容。只有實際存在的個案具有可讀頁；直接請求缺檔或未知個案時使用共用錯誤頁並回傳 HTTP 404。

### 資料工作台

工作台依影響分為：

- 本機資料處理：補齊缺少資料、格式化、處理原文、產生元數據、寫入彙編。
- 網路資料處理：自選主題維基、六十四卦維基。

每個操作標示「保留既有檔」、「寫入」或「需要網路／大量請求」。自選主題的起訖欄位只在該操作被選取時成為相關輸入，但伺服器始終執行完整驗證。

移除「執行全部操作」。送出按鈕在未選取操作時由前端停用；伺服器仍對空選取採 fail-safe 行為，不執行任何步驟。

處理函式改為回傳結構化報告，而非拼接單一字串。每個結果包含步驟名稱、`success`／`warning`／`error` 狀態及使用者可理解的訊息。工作台以逐項清單呈現報告；不可預期例外寫入伺服器記錄，畫面只顯示安全訊息。

第一階段仍採同步請求，不承諾即時百分比進度。送出時按鈕顯示處理中，完成後使用 POST → Redirect → GET，避免重新整理重複送出。

### 投影片

三套投影片保留現有資料與 `impress.js` 初始化。基底模板新增：

- 固定但不遮擋內容的控制列
- 上一頁、下一頁及返回首頁
- 目前頁數／總頁數
- 可開關的鍵盤操作說明
- `prefers-reduced-motion` 下縮短或取消非必要動畫

控制列使用 `impress.js` 的現有事件更新頁數，不改變投影片座標或內容生成器。

## 視覺系統與響應式行為

共用 CSS 定義色彩、字體、間距、圓角、陰影與內容寬度變數。主色為墨綠，背景為暖紙色，黃銅色只作為焦點與操作點綴。正文優先使用適合繁體中文的系統襯線字體 fallback，控制與導覽使用系統無襯線字體。

桌面首頁使用雙欄主視覺與四欄卦卡；窄螢幕改為單欄主視覺及兩欄卦卡。內容頁維持可讀行長，工作台在窄螢幕將分組與操作列垂直堆疊。不得產生水平捲動。

所有互動元素必須有明顯鍵盤焦點、足夠對比與可理解文字。狀態不能只靠顏色表達。所有頁面使用語意化的 `header`、`nav`、`main`、`section`、標題階層及表單標籤。

## 錯誤與恢復

- 核心卦名檔不存在時，首頁仍可載入，顯示資料尚未準備及前往工作台的修復提示。
- 個別卦文或維基內容缺少時，卦頁保留可用區段並分別標示缺失，不使整頁失敗。
- 風水個案缺檔時，首頁停用該項目；直接網址回傳友善 404。
- 工作台保留現有 CSRF、整數解析、起訖順序、最大範圍及預設不執行行為。
- 外部維基請求失敗只影響對應步驟，結構化報告標示失敗，不把未完成狀態誤報為成功。

## 測試策略

### 單元測試

- 內容目錄能建立 64 卦、3 套投影片與 10 筆個案描述。
- `001` 在現有資料下可讀，`002` 至 `010` 為不可讀並有缺檔原因。
- 搜尋文字包含卦序、卦名、類型與標題。
- 前後導覽在第一卦、中央卦及第 64 卦邊界正確。
- 結構化處理報告正確區分成功、警告與失敗。

### Flask 路由測試

- 首頁在完整資料與核心資料缺失兩種情況下皆可呈現。
- 工作台 GET、有效 POST、空選取、無效範圍及 CSRF 拒絕行為。
- 64 個卦路由可讀，範圍外路由有正確錯誤狀態。
- 可讀個案回傳 200；缺檔及未知個案回傳 404。
- 三個投影片路由持續回傳完整內容。

### 瀏覽器驗證

- 搜尋卦序、卦名、投影片及個案名稱。
- 類型篩選、空結果及清除搜尋。
- 缺檔個案沒有可點連結。
- 鍵盤可完成主導覽、搜尋、篩選及工作台選取。
- 桌面與手機寬度沒有水平溢出。
- 投影片控制、進度、說明及返回首頁可用。
- 代表頁面沒有瀏覽器主控台錯誤。

現有測試必須持續通過；與舊首頁表單或舊路徑綁定的測試應更新為新正式介面，不保留相容性測試。

## 驗收條件

1. 首頁可搜尋與篩選所有標題型內容，無 JavaScript 時仍能完整瀏覽。
2. 首頁顯示 10 筆個案，其中只有有內容檔者可開啟；目前資料應顯示 `1 / 10`。
3. `易經個案001` 能正常呈現；缺檔個案直接網址回傳 404。
4. 資料處理只存在於獨立工作台，沒有「全部操作」捷徑。
5. 卦文與個案頁使用共用閱讀版面及導覽。
6. 三套投影片保留原內容與動態，並有新增控制介面。
7. 桌面與手機排版、鍵盤操作、焦點、對比及減少動態偏好均通過驗證。
8. 自動測試、語法編譯、路由爬取及代表瀏覽器流程全部通過。
9. 實作提交不包含目前既有的 `config_data` 修改或其他使用者生成產物。
